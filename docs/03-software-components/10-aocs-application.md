### 3.10 AOCS Application

The AOCS Application runs the state-estimation and control algorithms.

It does not directly poll every sensor bus inside the model step. Instead:

1. Subsystem Interface Applications acquire and decode sensor data (Sensor Driver)
2. They publish normalised, timestamped measurements through the Software Bus.
3. The AOCS Application subscribes to those messages and maintains the latest coherent input set.
4. At each periodic release, it validates data age and validity.
5. It executes the model step.
6. It publishes normalised actuator requests through the Software Bus.

The AOCS model runner may call functions generated by Embedded Coder, for example:

```c
rtw_Model_initialize();
rtw_Model_step();
```

A wrapper around the autogenerated code is responsible for:

- Mapping Software Bus data into model inputs
- Validity flags
- Timestamp and data-age checks
- Model initialisation
- Execution-time profiling
- Publishing actuator commands
- Reporting faults and deadline misses

A representative input type is:

```c
typedef struct {
    uint64_t timestamp_us;
    bool valid;
    float value_imu[3];
    float value_etc;
} aocs_vector_measurement_t;
```

Protection logic that is outside the AOCS mathematical model should remain in manually developed software. This includes stale-data handling, hard inhibits, deadline supervision and fallback-state selection.
